# Markdown Reader v2 — Phase 3 (v2: editing, linked notes, folder-wide AI, MCP and mobile) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the product (`2.1.0`): edit mode, wiki-links and backlinks, AI over the whole folder (RAG, semantic search, related notes), writing assistant, read aloud, presentation mode, MCP server and Android/iOS versions.

**Architecture:** Same as the previous phases. The semantic index lives in SQLite (Rust, `rusqlite` with embedded SQLite) with brute-force cosine search. The MCP server is a second binary (`markdown-reader-mcp`) of the same crate, bundled as a *sidecar*. On mobile, the `NativeApi` boundary declares which capabilities exist and the UI hides the ones that don't.

**Tech Stack:** that of Phases 1-2 + CodeMirror 6, `rusqlite` (feature `bundled`), `rmcp` (official Rust MCP SDK), Web Speech API, Tauri mobile (Android/iOS).

**Spec:** `docs/REFACTOR-PLAN.md`. **Prerequisite:** the Phase 0-1 and Phase 2 plans (`2026-11-02-phase-0-1-foundation-and-mvp.md`, `2026-11-02-phase-2-v1-1.md`) are complete (tag `v2.0.0`). Type and function names from those plans are used here as-is.

## Global Constraints

- All Global Constraints from Phases 0-1 and 2 still apply.
- Version when the phase closes: `2.1.0`.
- Saving: always UTF-8 without BOM and atomic write (temp file in the same folder + rename). If the original file was not UTF-8, warn once before the first save.
- Semantic index in `<app_data_dir>/index.sqlite`; chunks of max. **1 500** characters with **200** of overlap, split by sections; top-**8** retrieval.
- The MCP server only reads files **inside** the given folder (canonicalized path with the root as prefix); it never writes.
- Tasks 1–8 are independent of each other except as stated under "Consumes"; Task 9 (mobile) goes last because it touches every capability.

## Review Focus

1. **Save conflict**: the file was modified outside the app while there were unsaved changes → never overwritten silently; offer "Reload (discard my changes)", "Overwrite" or "Save as". → test in Task 1.
2. **Closing a tab or the app with unsaved changes** → confirmation dialog; changes are never lost without asking. → test in Task 1.
3. **Path outside the folder in MCP** (`../../.ssh/id_rsa`, symlinks that leave the root, absolute paths) → rejected. → test in Task 7.
4. **Re-indexing after changes**: file edited, renamed or deleted → the index never returns stale chunks or chunks from deleted files. → test in Task 3.
5. **Ambiguous or broken wiki-link** (`[[Nota]]` when there are two `Nota.md` in different subfolders, or none) → pick the one closest to the current document's folder; if none exists, the link is shown as broken and does nothing. → test in Task 2.

// store.rs
pub struct IndexStore { /* rusqlite::Connection */ }
impl IndexStore {
  pub fn open(path: &Path) -> Result<Self, AppError>;
  pub fn upsert_file(&mut self, root: &str, path: &str, modified_ms: u64, chunks: &[Chunk], vectors: &[Vec<f32>], model: &str) -> Result<(), AppError>;
  pub fn remove_missing(&mut self, root: &str, existing: &[String]) -> Result<usize, AppError>;

}

#[serde(tag = "type", rename_all = "camelCase")] pub enum IndexProgress { Started { total: u32 }, File { done: u32, total: u32, path: String }, Done { indexed: u32, skipped: u32, removed: u32 }, Error { message: String } }

SQLite schema: `files(root TEXT, path TEXT, modified_ms INTEGER, model TEXT, PRIMARY KEY(root, path))`, `chunks(id INTEGER PRIMARY KEY, root TEXT, path TEXT, heading TEXT, line INTEGER, text TEXT, vector BLOB)` with an index on `(root, path)`; vectors as little-endian `f32`. Add a comment `// ponytail: brute force O(n); fine up to ~100k chunks, move to sqlite-vec if it falls short`.

Settings (added): `ai.embedPresetId`, `ai.embedBaseUrl`, `ai.embedModel` (default Ollama `http://localhost:11434/v1` and an empty model until the user picks one from `aiListModels`). Anthropic does not offer embeddings: if the chat provider is Anthropic, the index section asks to configure a separate embeddings provider.

- [ ] **Step 1:** `cargo add rusqlite --features bundled` · `cargo add async-trait`
- [ ] **Step 2: Tests** (with a `FakeEmbedder` that returns deterministic vectors from a hash of the text):
  - `chunk_markdown` of a document with 3 short sections → 3 chunks with their `heading` and `line`; a 4 000-character section → 3 chunks, each ≤ 1 500, and the start of each chunk repeats the last 200 of the previous one.
  - indexing twice without changes → the second returns `Done { indexed: 0, skipped: 2, removed: 0 }`; modifying a file (new mtime) → `indexed: 1`; deleting a file → `removed: 1` and `search` no longer returns its chunks; changing the embeddings model → reindexes everything.
  - `search` returns the chunk identical to the query first (score ≈ 1.0).
