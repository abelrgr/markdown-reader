# Markdown Reader v2 — Phase 2 (v1.1: folders, search, export, updates and basic AI) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the MVP into the first public release (`2.0.0`): folder mode, quick open, command palette, folder search, math, diagrams, export, reading themes, history, auto-update and AI features over the open document.

**Architecture:** Same as Phase 1. Heavy disk work (listing and searching folders) goes in Rust; rendering moves to a Web Worker; AI runs from Rust (API keys never enter the WebView) and streams to the frontend via `tauri::ipc::Channel`.

**Tech Stack:** Phase 1's stack + `ignore` (Rust), `reqwest` (stream), `keyring`, `tauri-plugin-updater`, `remark-math` + `rehype-katex`, `mermaid`, `remark-gemoji`, `remark-definition-list`.

**Spec:** `docs/REFACTOR-PLAN.md`. **Prerequisite:** the `2026-11-02-phase-0-1-foundation-and-mvp.md` plan must be finished (tag `v2.0.0-beta.1`). Type and function names from that plan are used here as-is.

## Global Constraints

- All Global Constraints of the Phase 0-1 plan still apply, except the network one, which is extended as follows: allowed connections = remote images (can be disabled), update checks (can be disabled) and the AI provider the user configures. AI is **disabled by default**.
- Version at the end of the phase: `2.0.0`.
- Limits: folder listing max. **10 000** files (`truncated: true` if exceeded); folder search max. **500** results; document context for AI max. **48 000** characters.
- API keys: only in the OS keychain (service `com.abelgallo.markdownreader`, account `ai:<presetId>`). Never in the store, never returned to the frontend, never in logs.
- Anthropic API (direct HTTP from Rust): `POST https://api.anthropic.com/v1/messages`, headers `x-api-key`, `anthropic-version: 2026-10-21`, `content-type: application/json`. Default model `claude-opus-5-5`. Do **not** send `temperature`, `top_p` or `top_k` (version `2026-10-21` rejects them). `max_tokens: 64000` with `stream: true`.
- OpenAI-compatible providers (Ollama, llama.cpp `llama-server`, LM Studio, OpenAI): `POST {baseUrl}/chat/completions` with `stream: true`; `GET {baseUrl}/models`. Do not send `temperature` either.
- Before the first request to a **remote** provider (host other than `localhost`/`127.0.0.1`/`::1`), ask for confirmation once per host: "The document content will be sent to {host}".

## Review Focus

1. **Huge folders or folders with `node_modules`/`.git`** (100 000 files) → the tree appears quickly, respects `.gitignore`, ignores hidden folders and marks "truncated" instead of hanging. → test in Task 4.
2. **Document with malicious instructions for the AI** ("ignore the above and …", or a fake `</document>`) → the prompt keeps the document delimited and escaped; the AI treats it as data. → test in Task 12.
3. **AI provider down, mistyped URL, invalid key or response cut off mid-stream** → readable error in the panel, the button becomes available again, no broken tabs. → tests in Tasks 11 and 12.
4. **Mermaid or KaTeX with invalid syntax** → the source code is shown with the error, the rest of the document stays rendered. → tests in Tasks 2 and 3.
5. **Folder search while the user keeps typing** → only the results of the latest query are shown (stale responses discarded). → test in Task 6.
